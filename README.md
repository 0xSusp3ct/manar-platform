# منصة مقياس منار للتميز التربوي المؤسسي

نسخة تشغيلية كاملة من منصة منار، تشمل طلبات التطبيق، رموز الدخول، التقييم المرحلي، حفظ النتائج، روابط التقارير الخاصة، PDF، Excel، لوحة الإدارة، وتوصيات المشرف.

الإصدار 2.2: يحافظ على التصور العصري المعتمد بألوان ب (أزرق رمادي) والغلاف البسيط ب، ويضيف الإصدار الفوري لرمز الدخول عبر البريد عند تهيئة Resend، والإظهار الصريح للرموز الجديدة للمالك مع حفظها مشفرة، وأرشفة النتائج واستعادتها دون حذفها نهائيًا. لوحة الشاشة مستقلة عن التقرير المطبوع؛ تعتمد صفحات PDF على قياس المحتوى بأبعاد A4، وتمتد النصوص الطويلة إلى صفحات إضافية. تحفظ تغييرات التقييم تلقائيًا ويستأنف التقدم بعد تحديث الصفحة.

## التشغيل المحلي

المتطلبات: Node.js 24.x وpnpm 11.19.0. دليل النشر الكامل: [المتطلبات وطريقة الرفع](DEPLOYMENT-AR.md).

1. انسخ `.env.example` إلى `.env` واملأ كلمة المرور ومفتاحًا عشوائيًا؛ لا تستخدم القيم التوضيحية. للتجربة المحلية غيّر `NODE_ENV=development` و`BASE_URL=http://localhost:3000` و`COOKIE_SECURE=false` و`TRUST_PROXY=0`، وأبق `PORT=3000` و`DATABASE_PATH=./data/manar.db`. لا تستخدم هذه القيم المحلية في الإنتاج.
2. شغّل `npx --yes pnpm@11.19.0 install --frozen-lockfile`.
3. شغّل `npx --yes pnpm@11.19.0 start`.
4. افتح `http://localhost:3000`، ولوحة الإدارة في `http://localhost:3000/admin`.

يُنشأ حساب المالك عند أول تشغيل فقط من `ADMIN_EMAIL` و`ADMIN_PASSWORD`. ويمكن تحديثه لاحقًا باستخدام:

```bash
pnpm create-admin owner@example.com "a-long-unique-password"
```

## ملف الاحتساب

- `SCORING_PROFILE=current50`: يحافظ على نسخة الموقع الحالية، 50 مؤشرًا وأوزان 30% / 30% / 40%.
- `SCORING_PROFILE=guide48`: يطابق الدليل المرفق، 48 مؤشرًا وإجمالي 240 درجة وحدود النضج الواردة فيه.

الإعداد الافتراضي `current50` يحافظ على نسخة الموقع. لا تتحول إلى `guide48` إلا باعتماد مالك المقياس، ولا تغيّر القيمة بعد وجود نتائج فعلية إلا ضمن ترحيل بيانات مخطط له.

## النشر

عند تعديل أي ملف في `public/`، شغّل `pnpm build:vercel-assets` قبل نشر نسخة Vercel حتى تتطابق المسارات التي يقدّمها المحول مع الواجهة الحديثة. يحافظ أمر البناء على مكتبات PDF المضمنة في المحول.

### Vercel مع Turso Cloud

تتضمن هذه النسخة محولًا جاهزًا لـ Vercel في `api/index.js` وقاعدة SQLite دائمة عبر تكامل Turso Cloud المجاني. بعد استيراد المستودع إلى Vercel:

1. ثبّت تكامل Turso Cloud واربط قاعدة جديدة بالمشروع؛ يضيف Vercel المتغيرين `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` تلقائيًا.
2. أضف `TOKEN_SECRET` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SCORING_PROFILE=current50` إلى متغيرات المشروع في Vercel. ولتفعيل الإرسال الفوري أضف أيضًا `RESEND_API_KEY` و`RESEND_FROM` بعد توثيق نطاق الإرسال والمرسل.
3. أعد نشر المشروع، ثم تحقق من `/api/health` وصفحة `/admin`.

تهيئ الدالة جداول قاعدة البيانات آليًا عند أول طلب. لا تحفظ قيم الأسرار داخل المستودع. ويمكن اختبار محول Vercel محليًا بالأمر `pnpm test:vercel`.

### الاستضافة التقليدية

المشروع تطبيق Node.js دائم التشغيل ويستخدم SQLite. يحتاج إلى استضافة تدعم:

- Node.js 24؛
- قرصًا دائمًا لملف قاعدة البيانات؛
- HTTPS ونطاقًا موثوقًا؛
- متغيرات بيئة آمنة؛
- نسخًا احتياطيًا دوريًا لقاعدة البيانات.

يمكن تشغيله بالحاوية المرفقة. اربط مسار `/app/data` بقرص دائم، واضبط `DATABASE_PATH=/app/data/manar.db`.

GitHub Pages وحده لا يكفي للنسخة الآمنة لأنه لا يشغّل قاعدة بيانات أو مصادقة أو خدمة إرسال. يمكن إبقاء المستودع للشفرة، لكن التشغيل يجب أن يكون على استضافة تطبيقات أو خادم مناسب.

## البريد عبر Resend

اضبط `RESEND_API_KEY` و`RESEND_FROM` بعد توثيق نطاق الإرسال وعنوان المرسل لدى Resend في متغيرات بيئة الخادم أو Vercel، ثم أعد النشر ونفّذ اختبار إرسال حقيقي. عند اكتمال الإعداد يصدر طلب التسجيل العام رمز دخول فورًا، ويرسله إلى البريد المسجل، ثم يحوّل الطلب إلى «معتمد». إذا تعذر التسليم، يُلغى الرمز الذي لم يسلّم بأمان ويبقى الطلب «قيد المراجعة» ليعالجه المالك. وعند عدم ضبط البريد من الأساس تستمر المنصة بالعمل بنمط الاعتماد والمشاركة اليدوية. كما ترسل المنصة رابط التقرير إلى بريد الطلب بعد اكتمال التقييم عندما تكون الخدمة مهيأة.

تفاصيل متابعة الملاحظات المجانية ومدخلات العميل المطلوبة: [متابعة الملاحظات](docs/FREE-FOLLOWUP-AR.md).

## المتبقي للتفعيل الكامل

- نطاق إرسال وعنوان مرسل موثّقان لدى Resend، مع `RESEND_API_KEY` فعال واختبار وصول حقيقي للرمز والتقرير.
- الشعار الرسمي بصيغة SVG أصلية، أو PNG شفاف عالي الدقة إذا لم يتوفر SVG.
- اعتماد مالك المقياس ملف الاحتساب النهائي: `current50` الحالي أو `guide48` المطابق للدليل، قبل جمع بيانات فعلية.

## الحماية

- رموز الدخول الجديدة عالية العشوائية؛ تحفظ بصمة HMAC للتحقق ونسخة مشفرة موثقة بـ AES-256-GCM حتى يستطيع المالك إظهارها عند الطلب فقط. لا تعاد الرموز القديمة السابقة للإصدار 2.2 من بصمتها، لذلك لا يمكن إظهارها إذا لم تكن لها نسخة مشفرة.
- روابط التقارير عالية العشوائية ولا تخزن بصورتها الأصلية.
- جلسات الإدارة والتقييم في Cookies محمية و`SameSite=Strict`.
- رموز الدخول تستخدم مرة واحدة وتغلق بعد إرسال التقييم.
- الإجابات لا توضع في الرابط، والتقرير للعرض فقط.
- أرشفة النتيجة عملية مالك فقط، وتوقف عرض التقرير والمشاركة والتصدير والتعديل حتى استعادتها.
- تحقق خادمي من المدخلات والإجابات، وحدود على الطلبات ومحاولات الدخول.
- رؤوس أمان وCSP ومنع تضمين الصفحات داخل إطارات.
- فصل دور المالك عن مشرف التقارير.

هذه طبقة حماية أساسية وفق العقد وليست اختبار اختراق أو شهادة مستقلة.

## الاختبار

شغّل `pnpm test`. يغطي الاختبار مسار الطلب والإصدار الفوري وفشل التسليم الآمن، وتشفير الرمز وإظهاره بصلاحية المالك، والتقييم والحفظ والنتيجة غير القابلة للتعديل، وأرشفة النتائج واستعادتها، والتقرير والتوصيات وExcel وفصل الصلاحيات.

يشمل أيضًا 119 تحققًا من الاحتساب بملفيه، والمدخلات، والروابط، والجلسات، وحدود الطلبات، ومنع كشف الرمز أو إظهار رمز قديم أو متلاعب به. يستخدم الاختبار خدمة بريد وهمية ولا يرسل بريدًا حقيقيًا أو يستخدم بيانات تشغيلية.

اختبار المتصفح: `pnpm test:browser`. مكتبة Playwright مثبتة ضمن تبعيات التطوير؛ على Windows يستخدم الاختبار Microsoft Edge تلقائيًا عند توفره. في البيئات الأخرى نفّذ `pnpm exec playwright install chromium` مرة واحدة، أو اضبط `BROWSER_EXECUTABLE` لمسار Chromium/Edge. يمكن ضبط `PLAYWRIGHT_MODULE` لمسار بديل للمكتبة و`QA_OUTPUT` لمجلد النتائج. ينشئ الاختبار قاعدة بيانات مؤقتة في الذاكرة، ويجرب رحلة التقييم الكاملة والجوال والطباعة والنصوص الطويلة. ملفات المعاينة تحمل بيانات تجريبية فقط.

حاوية Docker تستخدم pnpm وملف القفل المرفق. القرص `/app/data` يجب أن يكون قابلًا للكتابة بواسطة مستخدم `node` داخل الحاوية. لا تُنسخ قاعدة البيانات أو `.env` أو `node_modules` إلى الصورة.

## قبل الإطلاق

راجع [دليل النشر](DEPLOYMENT-AR.md) و[دليل المالك](docs/OWNER-GUIDE-AR.md). لا تضع ملف `.env` أو قاعدة البيانات داخل Git أو مستودع عام. احفظ قاعدة البيانات و`TOKEN_SECRET` عند كل تحديث.

تتضمن الحزمة الواجهة والخادم والاختبارات وإعدادات التشغيل. لا تتضمن بيانات تقييم أو أسرارًا أو مكتبات `node_modules`؛ تثبّت المكتبات بالأمر أعلاه، وتُنشأ قاعدة البيانات وحساب المالك عند أول تشغيل. صفحة البداية هي `public/index.html` ويقدّمها الخادم تلقائيًا. لا توجد خطوة بناء مستقلة للواجهة.
