# منصة مقياس منار للتميز التربوي المؤسسي

نسخة تشغيلية كاملة من منصة منار، تشمل طلبات التطبيق، رموز الدخول، التقييم المرحلي، حفظ النتائج، روابط التقارير الخاصة، PDF، Excel، لوحة الإدارة، وتوصيات المشرف.

الإصدار 2.1: التصور العصري المعتمد بألوان ب (أزرق رمادي)، والغلاف البسيط ب. لوحة الشاشة مستقلة عن التقرير المطبوع. تعتمد صفحات PDF على قياس المحتوى بأبعاد A4 وتتمدد النصوص الطويلة إلى صفحات إضافية. تحفظ تغييرات التقييم تلقائيًا ويستأنف التقدم بعد تحديث الصفحة.

## التشغيل المحلي

المتطلبات: Node.js 24.x وpnpm 11.19.0. دليل النشر الكامل: [المتطلبات وطريقة الرفع](DEPLOYMENT-AR.md).

1. انسخ `.env.example` إلى `.env` واملأ كلمة المرور ومفتاحًا عشوائيًا؛ لا تستخدم القيم التوضيحية. للتجربة المحلية غيّر `NODE_ENV=development` و`BASE_URL=http://localhost:3000` و`COOKIE_SECURE=false` و`TRUST_PROXY=0`، وأبق `PORT=3000` و`DATABASE_PATH=./data/manar.db`. لا تستخدم هذه القيم المحلية في الإنتاج.
2. شغّل `npx --yes pnpm@11.19.0 install --frozen-lockfile`.
3. شغّل `npx --yes pnpm@11.19.0 start`.
4. افتح `http://localhost:3000`، ولوحة الإدارة في `http://localhost:3000/admin`.

يُنشأ حساب المالك عند أول تشغيل فقط من `ADMIN_EMAIL` و`ADMIN_PASSWORD`. ويمكن تحديثه لاحقًا باستخدام:

```bash
pnpm create-admin owner@example.com "a-long-unique-password"
```

## ملف الاحتساب

- `SCORING_PROFILE=current50`: يحافظ على نسخة الموقع الحالية، 50 مؤشرًا وأوزان 30% / 30% / 40%.
- `SCORING_PROFILE=guide48`: يطابق الدليل المرفق، 48 مؤشرًا وإجمالي 240 درجة وحدود النضج الواردة فيه.

الإعداد الافتراضي `current50` يحافظ على نسخة الموقع. لا تتحول إلى `guide48` إلا باعتماد مالك المقياس، ولا تغيّر القيمة بعد وجود نتائج فعلية إلا ضمن ترحيل بيانات مخطط له.

## النشر

### Vercel مع Turso Cloud

تتضمن هذه النسخة محولًا جاهزًا لـ Vercel في `api/index.js` وقاعدة SQLite دائمة عبر تكامل Turso Cloud المجاني. بعد استيراد المستودع إلى Vercel:

1. ثبّت تكامل Turso Cloud واربط قاعدة جديدة بالمشروع؛ يضيف Vercel المتغيرين `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` تلقائيًا.
2. أضف `TOKEN_SECRET` و`ADMIN_EMAIL` و`ADMIN_PASSWORD` و`SCORING_PROFILE=current50` إلى متغيرات المشروع في Vercel.
3. أعد نشر المشروع، ثم تحقق من `/api/health` وصفحة `/admin`.

تهيئ الدالة جداول قاعدة البيانات آليًا عند أول طلب. لا تحفظ قيم الأسرار داخل المستودع. ويمكن اختبار محول Vercel محليًا بالأمر `pnpm test:vercel`.

### الاستضافة التقليدية

المشروع تطبيق Node.js دائم التشغيل ويستخدم SQLite. يحتاج إلى استضافة تدعم:

- Node.js 24؛
- قرصًا دائمًا لملف قاعدة البيانات؛
- HTTPS ونطاقًا موثوقًا؛
- متغيرات بيئة آمنة؛
- نسخًا احتياطيًا دوريًا لقاعدة البيانات.

يمكن تشغيله بالحاوية المرفقة. اربط مسار `/app/data` بقرص دائم، واضبط `DATABASE_PATH=/app/data/manar.db`.

GitHub Pages وحده لا يكفي للنسخة الآمنة لأنه لا يشغّل قاعدة بيانات أو مصادقة أو خدمة إرسال. يمكن إبقاء المستودع للشفرة، لكن التشغيل يجب أن يكون على استضافة تطبيقات أو خادم مناسب.

## البريد عبر Resend

اضبط `RESEND_API_KEY` و`RESEND_FROM` بعد توثيق النطاق لدى Resend. عند عدم ضبطهما تستمر المنصة بالعمل، وتعرض الإدارة الرمز أو الرابط للنسخ اليدوي دون إرسال بريد.

## الحماية

- رموز الدخول وروابط التقارير عالية العشوائية ولا تخزن بصورتها الأصلية.
- جلسات الإدارة والتقييم في Cookies محمية و`SameSite=Strict`.
- رموز الدخول تستخدم مرة واحدة وتغلق بعد إرسال التقييم.
- الإجابات لا توضع في الرابط، والتقرير للعرض فقط.
- تحقق خادمي من المدخلات والإجابات، وحدود على الطلبات ومحاولات الدخول.
- رؤوس أمان وCSP ومنع تضمين الصفحات داخل إطارات.
- فصل دور المالك عن مشرف التقارير.

هذه طبقة حماية أساسية وفق العقد وليست اختبار اختراق أو شهادة مستقلة.

## الاختبار

شغّل `pnpm test`. يغطي الاختبار مسار الطلب والاعتماد والرمز والتقييم والحفظ والنتيجة غير القابلة للتعديل والتقرير والتوصيات وExcel وفصل الصلاحيات.

يشمل أيضًا 57 تحققًا من الاحتساب بملفيه، المدخلات، الروابط، الجلسات وحد الطلبات. لا يرسل الاختبار بريدًا ولا يستخدم بيانات تشغيلية.

اختبار المتصفح: `pnpm test:browser` بعد توفير Playwright، أو ضبط `PLAYWRIGHT_MODULE` إلى ملف `playwright/index.mjs`. اضبط `BROWSER_EXECUTABLE` لمسار متصفح Chromium/Edge و`QA_OUTPUT` لمجلد نتائج الاختبار. ينشئ الاختبار قاعدة بيانات مؤقتة في الذاكرة، ويجرب رحلة التقييم الكاملة والجوال والطباعة والنصوص الطويلة. ملفات المعاينة تحمل بيانات تجريبية.

حاوية Docker تستخدم pnpm وملف القفل المرفق. القرص `/app/data` يجب أن يكون قابلًا للكتابة بواسطة مستخدم `node` داخل الحاوية. لا تُنسخ قاعدة البيانات أو `.env` أو `node_modules` إلى الصورة.

## قبل الإطلاق

راجع [دليل النشر](DEPLOYMENT-AR.md) و[دليل المالك](docs/OWNER-GUIDE-AR.md). لا تضع ملف `.env` أو قاعدة البيانات داخل Git أو مستودع عام. احفظ قاعدة البيانات و`TOKEN_SECRET` عند كل تحديث.

تتضمن الحزمة الواجهة والخادم والاختبارات وإعدادات التشغيل. لا تتضمن بيانات تقييم أو أسرارًا أو مكتبات `node_modules`؛ تثبّت المكتبات بالأمر أعلاه، وتُنشأ قاعدة البيانات وحساب المالك عند أول تشغيل. صفحة البداية هي `public/index.html` ويقدّمها الخادم تلقائيًا. لا توجد خطوة بناء مستقلة للواجهة.
